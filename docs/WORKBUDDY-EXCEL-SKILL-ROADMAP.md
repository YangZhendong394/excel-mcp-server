# WorkBuddy Excel Skill — 功能扩展与专业版开发蓝图

> 状态：规划基线（尚未代表功能已实现）
> 当前基线：`excel-workbook-assistant-lite`，`2.0.0-alpha.1`
> 目标：把当前四命令原型升级为可承担日常办公、数据整理和专业分析任务的离线 Excel Skill。
> 维护者：没皮没脸。上游 Excel MCP Server 的原作者版权与 MIT 许可继续保留，详见仓库 LICENSE 和 THIRD_PARTY_NOTICES。

## 1. 产品目标与发布原则

本项目不再以“能读写 Excel 文件”作为收费产品标准。目标产品应能完成三类任务：

1. **日常办公操作**：工作簿/工作表管理、数据编辑、排序查找、格式布局、表格、图表、CSV。
2. **专业数据工作**：数据质量检查、清洗、汇总、对账、统计分析、财务分析、经营报表。
3. **高级 Excel 能力**：原生数据透视表、复杂图表、公式追踪/求解、大型工作簿和特殊 OOXML 对象处理。

### 不可破坏的产品约束

- 普通 WorkBuddy Skill；运行时不启动 MCP Server，不要求用户配置 MCP 或 Connector。
- 离线运行；首次使用和日常操作都不自动联网、不执行 pip/uv 安装。
- 上传 ZIP 必须低于 WorkBuddy 3 MB 限制，并预留增长空间；每次 CI 打包都检查最终 ZIP 大小。
- 用户原文件默认只读；修改默认另存为一个不存在的新文件，不覆盖原件。
- 每次修改都做输入校验、文件容器校验、大小/解压限制和安全保存；失败时不能留下半成品。
- 继续支持 WorkBuddy Windows x64 / CPython 3.13 的实机验收；如要扩展平台，需单独增加对应实测。
- 保留上游 MIT LICENSE、原作者署名及第三方依赖许可证。
- 不把“能够保留已有对象”计作“能够创建或编辑该对象”。
- 未经自动化测试和 WorkBuddy 实机验收的能力，不标记为“已完成”或宣传为稳定支持。

## 2. 当前代码审查结论

当前轻量 Skill 的实际 CLI 只有 `create`、`inspect`、`read`、`write` 四个命令，基础实现集中在：
`workbuddy-skill/excel-workbook-assistant-lite/scripts/excel_workbook.py`。

同一仓库已保留上游的模块化实现，包含：

- `src/excel_mcp/operations/`：单元格、排序、转换、格式、布局、工作表、CSV、图表、表格、批注、名称、透视表等业务操作。
- `src/excel_mcp/calc/`：公式解析、计算、依赖关系、统计/财务/文本/日期等函数。
- `src/excel_mcp/package/`：OOXML 包部件扫描、保存、恢复、扩展对象和特殊部件处理。
- `src/excel_mcp/server/`：MCP 工具入口和参数/注册层。

上游工程的发行依赖还包含 MCP、Pydantic、Starlette、Uvicorn、Pillow、olefile 等。普通 Skill 不能直接复制整套 MCP 服务端和依赖栈，否则会破坏轻量、离线和 3 MB 包体目标。

### 技术路线决定

**复用底层业务逻辑，重写轻量命令适配层。**

- 优先从 `operations` 中复用不依赖 MCP 的算法；依赖 Pydantic 数据模型的部分，改为轻量参数解析或小型标准数据结构。
- 命令层只负责参数解析、权限/路径限制、加载工作簿、调用操作、另存副本和输出 JSON 收据。
- 不导入 `mcp.server`、Starlette、Uvicorn 等服务层。
- 不默认引入 pandas、numpy、scipy 等大型运行时依赖；统计和财务计算优先用 Python 标准库实现。确有必要时先核算包体、许可证和离线兼容性，再决定。
- 专业分析算法和 Excel 文件写入分层：先计算并生成可核对结果，再由独立输出模块写回工作簿。

## 3. 版本路线与功能清单

状态定义：
- **现有**：当前原型已具备，并已完成对应测试。
- **待开发**：目标范围内，但尚未实现。
- **后置**：技术复杂度高或风险高，先不作为首轮收费发布承诺。
- **不纳入普通 Skill**：涉及执行宏、调用外部服务或无法满足安全边界的能力。

### 阶段 B — 专业数据分析（产品差异化卖点）

这些能力不只是 Excel 对象编辑，而是能回答业务问题并生成可交付结果。先采用 Python 计算，再输出结果表、解释和图表。

| ID | 专业功能 | 计划内容 | 结果交付 |
|---|---|---|---|
| B01 | 数据画像 | 字段类型、空值、唯一值、重复率、分布、极值、异常格式 | 数据质量报告工作表 + JSON 摘要 |
| B02 | 数据清洗 | 去空行、去重复、文本清理、统一日期/数字、缺失值处理、标准化分类 | 清洗后副本 + 清洗日志 |
| B03 | 分组汇总 | 按一个或多个字段分组，count/sum/avg/min/max；支持多指标 | 汇总表 + 排名 |
| B04 | 交叉分析 | 双维度交叉表、行列总计、占比和排序 | 交叉分析工作表 |
| B05 | 多表合并 | 按键字段合并多个工作表/文件，支持 inner/left/full 的明确语义 | 合并结果 + 未匹配记录 |
| B06 | 数据对账 | 按主键比较两份数据，区分新增、删除、变更、相同、重复键 | 对账差异报告 |
| B07 | 统计分析 | 描述性统计、分位数、标准差、相关性、简单线性回归 | 统计报告 + 可选图表 |
| B08 | 财务分析 | 毛利率/净利率、同比/环比、CAGR、盈亏平衡、NPV、IRR、贷款摊还 | 财务分析表 + 公式/口径说明 |
| B09 | 趋势与预测 | 移动平均、线性趋势、季节性基础检查；报告假设和误差 | 预测结果 + 历史拟合指标 |
| B10 | 异常检测 | IQR/Z-score 等明确方法；输出异常点和阈值，不自动删数据 | 异常清单 + 标注副本 |
| B11 | 经营报表 | KPI、月度趋势、产品/区域/客户贡献、Top/Bottom 排名 | 新建仪表板工作表 + 图表 |
| B12 | 公式审计 | 公式错误、公式模式不一致、引用异常、常量混入公式区域 | 定位清单；默认不自动改公式 |

专业分析口径要求：
- 所有计算必须注明字段、过滤条件、分母、时间范围和算法口径。
- 对空值、重复键、无效日期、文本数字和异常值不能静默处理；必须计数并写入日志。
- 财务/统计结果要用独立测试数据与人工可复算的参考值比对。
- 预测结果是统计估计，不得写成确定性承诺；必须输出方法、窗口、数据量和局限。
- 默认生成新的分析工作表或文件，不修改原始数据源。
- 每个结果都要保留来源范围和汇总条件，方便追溯。

## 4. 建议的 CLI 命令结构

保留现有 `create`、`inspect`、`read`、`write` 参数兼容性，新增清晰的命令族，不将所有功能塞进一个无限膨胀的脚本：

- `workbook`：list、inspect、settings、create。
- `sheet`：list、create、rename、copy、delete、visibility。
- `range`：read、write、clear、copy、sort、find、replace、transform。
- `rows` / `columns`：insert、delete、size、visibility。
- `format`：cells、merge、layout、conditional、validation。
- `table`：create、inspect、update、delete。
- `chart`：create、inspect、delete。
- `csv`：import、export。
- `analyze`：profile、clean、summarize、cross-tab、compare、stats、finance、forecast、outliers、report、formula-audit。

命令最终形态以实际测试和 WorkBuddy 调用可靠性为准。一个命令可以有明确子操作，但不能把多个互不相关的功能藏在一个模糊的“万能操作”里。

## 5. 模块化代码布局建议

在 Skill 的 `scripts/` 下逐步拆分：

- `cli.py`：统一入口和子命令注册。
- `safety.py`：路径授权、文件容器检查、大小限制、原件保护、原子另存。
- `workbook_ops.py`：工作簿与工作表操作。
- `range_ops.py`：区域读写、复制、清空、排序、查找替换和转换。
- `format_ops.py`：格式、布局、条件格式、数据验证。
- `object_ops.py`：表格、图表、超链接、批注。
- `csv_ops.py`：安全 CSV 读写。
- `analysis/quality.py`：数据画像、清洗和异常检查。
- `analysis/summary.py`：分组汇总、交叉表和对账。
- `analysis/statistics.py`：描述性统计、相关性、回归。
- `analysis/finance.py`：财务指标与现金流计算。
- `analysis/report.py`：分析表、KPI 和图表生成。
- `tests/`：每个模块独立的自动化验收样本。

公共安全层只能有一份，禁止每个命令分别实现一套文件路径或保存逻辑。

## 6. 测试与验收标准

### 每个新增读操作
- 正常数据、空表、隐藏工作表、无效工作表名、无效范围。
- 大范围分页/上限检查，结果行列和单元格地址准确。
- 公式表达式、公式缓存值分清，不把空缓存伪装成计算结果。

### 每个新增写操作
- 输出为新文件；源文件 SHA-256 和 mtime 不变。
- 输出文件可重新打开；目标值/格式/对象回读与预期一致。
- 输出文件名冲突、路径越权、非法 XML 字符、超限输入必须安全拒绝。
- 对涉及引用的插删行列操作，检查公式、定义名称、表格、筛选、条件格式、数据验证、合并区域和图表引用。
- 对 xlsm 检查 `vbaProject.bin`；其他宏相关部件按实际样本独立声明，不能扩大保证。

### 专业分析
- 准备小型、可人工复算的固定测试集。
- 对每个算法定义结果口径和边界样本（空值、重复、负数、零分母、日期缺口、异常值）。
- 以独立参考结果作数值断言，不能只断言脚本返回 `ok=true`。
- 对输入数据无损；清洗结果输出到副本；保存处理日志和摘要。

### 兼容性与发布
- WorkBuddy Windows x64 / CPython 3.13 无安装、无联网实机测试。
- ZIP 小于 3 MB；依赖清单、许可证、文件清单自动检查。
- xlsx、xlsm、损坏文件、受保护/特殊对象样本都有记录。
- 功能矩阵逐项标注：已实现并自动测试、已实机验收、部分支持、未实现、明确不支持。
- 不以“支持 46 项”作为目标口号；只按真正通过测试的原子能力计数。

## 7. 建议的实施顺序

1. **先重构底座，不先加功能**：将当前单文件脚本拆分为安全层、工作簿层、区域层和 CLI 层；保持现有四命令测试不回退。
2. **先做阶段 A 的数据操作**：sheet 管理、清空/复制、排序、查找替换、去重、文本分列、填充。
3. **再做阶段 A 的格式与对象**：格式、布局、条件格式、验证、表格、CSV、基础图表。
4. **做专业分析底座**：数据画像、清洗日志、分组汇总、对账；以上是最容易形成用户感知价值的专业能力。
5. **加入统计/财务/报表**：先固定口径和参考数据，再开发算法，最后写入 Excel。
6. **最后评估 PivotTable、公式引擎和 OOXML 深度保护**：按专项项目处理，避免拖累日常功能交付。

## 8. 里程碑与发布门槛

| 里程碑 | 交付物 | 发布含义 |
|---|---|---|
| M0 技术重构 | 模块化脚本、安全层、旧测试不回退 | 仍为内部 Alpha |
| M1 日常办公 | 阶段 A 高优先级功能、命令文档、测试矩阵 | 可开始内部试用，不自动代表收费发布 |
| M2 专业分析 | 数据质量、汇总、对账、统计/财务、报表 | 形成收费候选版核心卖点 |
| M3 兼容性强化 | xlsx/xlsm 回归、特殊对象矩阵、体积/性能验收 | 达到候选发布评审条件 |
| M4 高级 Excel | PivotTable、公式追踪等后置能力 | 作为后续版本增强，不阻塞首个专业版本 |

**收费发布最低门槛**：
- 阶段 A 的所有 P0 及约定 P1 完成并通过自动化测试；
- 阶段 B 至少交付数据画像、清洗、分组汇总、对账、统计分析、财务分析和经营报表；
- WorkBuddy 实机全流程验收通过；
- 所有已知兼容性限制清楚列出；
- ZIP、许可证、上游署名、作者信息、版本号和发布说明全部核对；
- 没有未解决的高严重度数据损坏或覆盖风险。
